# Hauth v0.1 Compatibility Contract

This document is the target contract for Hauth v0.1. It describes the
Supabase Auth compatible surface Hauth commits to implement before the v0.1
milestone is complete. Endpoints marked as placeholders are served for path
compatibility but intentionally return `501 Not Implemented`.

Endpoint paths are relative to the Hauth Auth base URL. For drop-in Supabase
deployments, operators should expose that base URL at `/auth/v1`.

## Compatibility Goals

Hauth v0.1 commits to:

- Preserve the Supabase Auth REST paths listed in this document.
- Preserve the Supabase JWT claim names used by Postgres RLS policies.
- Preserve the core `auth` schema table names needed by existing RLS and
  PostgREST integrations.
- Support email/password signup and login, refresh token rotation, password
  recovery, email verification, Google OAuth, GitHub OAuth, TOTP MFA, sessions,
  and a basic service-role admin API.

Hauth v0.1 does not commit to bug-for-bug compatibility with GoTrue. When Hauth
intentionally differs, the behavior must be documented here before release.

## Headers And Auth Modes

All JSON requests use:

```http
Content-Type: application/json
```

Public endpoints are anonymous. They must tolerate Supabase client `apikey`
headers so existing clients do not fail because they send them.

Session endpoints require:

```http
Authorization: Bearer <access_token>
```

Admin endpoints require:

```http
Authorization: Bearer <service_role_token>
```

The service-role token is privileged server-side material. It must never be
accepted from browser-only flows or exposed in generated client examples.

## Endpoint Status

Status values:

- `implemented`: endpoint is part of the active v0.1 behavior.
- `placeholder`: endpoint is served for compatibility and returns `501`.
- `out of scope`: endpoint is not served as a v0.1 commitment.

Placeholder response body:

```json
{
  "code": "not_implemented",
  "msg": "Not implemented"
}
```

| Endpoint | Status |
| --- | --- |
| `GET /healthz`, `GET /healthz/deep`, `GET /settings` | implemented |
| `POST /signup`, `POST /token`, `POST /recover`, `POST /verify`, `POST /resend` | implemented |
| `GET /authorize`, `GET /callback` | implemented |
| `GET /user`, `PUT /user`, `POST /logout` | implemented |
| `GET /factors`, `POST /factors`, `POST /factors/{factor_id}/challenge`, `POST /factors/{factor_id}/verify` | implemented |
| `DELETE /factors/{factor_id}` | placeholder |
| `GET /admin/users`, `POST /admin/users`, `GET /admin/users/{user_id}`, `PUT /admin/users/{user_id}`, `DELETE /admin/users/{user_id}` | implemented |
| `GET /admin/users/{user_id}/identities` | implemented |
| `DELETE /admin/users/{user_id}/identities/{identity_id}` | placeholder |
| `POST /admin/generate_link` | placeholder |
| `POST /admin/invite` | implemented |
| `GET /admin/providers`, `PUT /admin/providers` | placeholder |
| `GET /admin/email_templates`, `PUT /admin/email_templates` | placeholder |
| `GET /admin/email-templates`, `GET /admin/email-templates/{name}`, `PUT /admin/email-templates/{name}`, `DELETE /admin/email-templates/{name}` | implemented |
| `POST /admin/webhooks`, `GET /admin/webhooks`, `GET /admin/webhooks/{subscription_id}`, `PUT /admin/webhooks/{subscription_id}`, `DELETE /admin/webhooks/{subscription_id}` | implemented |
| `GET /admin/webhooks/{subscription_id}/deliveries`, `GET /admin/deliveries/{delivery_id}`, `POST /admin/deliveries/{delivery_id}/retry` | implemented |
| `GET /admin/webhook_deliveries`, `GET /admin/webhook_deliveries/{delivery_id}`, `POST /admin/webhook_deliveries/{delivery_id}/retry` | placeholder |
| Phone/SMS, anonymous users, WebAuthn/passkeys, SAML/SSO, `/reauthenticate`, admin audit log endpoints | out of scope |

## Supported Endpoint Contract

### General

#### `GET /healthz`

Returns process-level health.

Response `200`:

```json
{
  "healthStatus": "ok"
}
```

#### `GET /healthz/deep`

Returns dependency-aware health.

Response `200`:

```json
{
  "deepHealthStatus": "ok",
  "deepHealthChecks": ["process", "config", "database"]
}
```

When a dependency is unhealthy, this endpoint must return a non-2xx response
with a JSON body identifying the failed check.

#### `GET /settings`

Returns public Auth settings needed by clients.

Response `200`:

```json
{
  "disable_signup": false,
  "mailer_autoconfirm": false,
  "mfa_enabled": true,
  "external": {
    "email": true,
    "github": true,
    "google": true
  }
}
```

### Email And Password

#### `POST /signup`

Creates an email/password user.

Request:

```json
{
  "email": "user@example.com",
  "password": "correct horse battery staple",
  "data": {
    "display_name": "Ada"
  }
}
```

If email confirmation is enabled, response `200` is a user object and no
session is issued:

```json
{
  "id": "00000000-0000-0000-0000-000000000000",
  "aud": "authenticated",
  "role": "authenticated",
  "email": "user@example.com",
  "email_confirmed_at": null,
  "confirmed_at": null,
  "confirmation_sent_at": "2026-05-28T00:00:00Z",
  "app_metadata": {
    "provider": "email",
    "providers": ["email"]
  },
  "user_metadata": {
    "display_name": "Ada"
  },
  "identities": [],
  "factors": [],
  "created_at": "2026-05-28T00:00:00Z",
  "updated_at": "2026-05-28T00:00:00Z"
}
```

If email confirmation is disabled, response `200` is a session response.

#### `POST /token?grant_type=password`

Signs in an email/password user.

Request:

```json
{
  "email": "user@example.com",
  "password": "correct horse battery staple"
}
```

Response `200`:

```json
{
  "access_token": "<jwt>",
  "token_type": "bearer",
  "expires_in": 3600,
  "refresh_token": "<opaque-refresh-token>",
  "user": {
    "id": "00000000-0000-0000-0000-000000000000",
    "aud": "authenticated",
    "role": "authenticated",
    "email": "user@example.com",
    "app_metadata": {
      "provider": "email",
      "providers": ["email"]
    },
    "user_metadata": {},
    "created_at": "2026-05-28T00:00:00Z",
    "updated_at": "2026-05-28T00:00:00Z"
  }
}
```

#### `POST /token?grant_type=refresh_token`

Rotates a refresh token and returns a new session.

Request:

```json
{
  "refresh_token": "<opaque-refresh-token>"
}
```

Response `200` is the same session response shape used by the password grant.
The supplied refresh token must become invalid after successful rotation.

Supported grant types in v0.1 are exactly:

- `password`
- `refresh_token`

The `id_token`, `pkce`, `otp`, `magiclink`, `phone`, and SSO grant surfaces are
not v0.1 commitments.

#### `POST /recover`

Requests a password recovery email.

Request:

```json
{
  "email": "user@example.com"
}
```

Response `200`:

```json
{}
```

This response must not reveal whether the email exists.

#### `POST /verify`

Verifies email action tokens.

Request:

```json
{
  "type": "signup",
  "token": "confirmation-code-delivered-in-email"
}
```

Supported v0.1 `type` values:

- `signup`
- `recovery`
- `invite`
- `email_change`

Response `200` is a session response when verification signs the user in.
Password recovery verification must allow the authenticated follow-up
`PUT /user` password update.

#### `POST /resend`

Resends an existing email action.

Request:

```json
{
  "email": "user@example.com",
  "type": "signup"
}
```

Supported v0.1 `type` values:

- `signup`
- `email_change`

Response `200`:

```json
{}
```

### User Session

#### `GET /user`

Returns the current authenticated user.

Response `200` is the user object shape from `/signup`.

#### `PUT /user`

Updates the current authenticated user.

Request:

```json
{
  "email": "new@example.com",
  "password": "new password",
  "data": {
    "display_name": "Ada Lovelace"
  }
}
```

All fields are optional, but at least one must be present. Response `200` is
the updated user object.

#### `POST /logout`

Revokes refresh tokens for the authenticated user.

Optional query:

```http
POST /logout?scope=global
```

Supported v0.1 scope values:

- `global`: revoke every active session for the user; default.
- `local`: revoke only the current session.
- `others`: revoke all sessions except the current session.

Response `204` with no body. Existing access tokens remain valid until their
`exp` time.

### OAuth

#### `GET /authorize`

Starts an OAuth flow.

Query parameters:

- `provider`: required, one of `google` or `github`.
- `redirect_to`: optional allowed redirect URL.
- `scopes`: optional provider-specific scope string.

Response `302` redirects to the provider authorization URL.

#### `GET /callback`

Completes an OAuth flow after provider redirect.

Query parameters:

- `code`: provider authorization code.
- `state`: Hauth state value created by `/authorize`.

Response `302` redirects to the configured application URL with session fields
in the URL fragment:

```text
#access_token=<jwt>&token_type=bearer&expires_in=3600&refresh_token=<token>&provider=<provider>
```

### TOTP MFA

#### `GET /factors`

Lists the current user's factors.

Response `200`:

```json
{
  "totp": [
    {
      "id": "00000000-0000-0000-0000-000000000000",
      "factor_type": "totp",
      "friendly_name": "Phone authenticator",
      "status": "verified"
    }
  ]
}
```

#### `POST /factors`

Starts TOTP enrollment.

Request:

```json
{
  "factor_type": "totp",
  "friendly_name": "Phone authenticator",
  "issuer": "Hauth"
}
```

Response `200`:

```json
{
  "id": "00000000-0000-0000-0000-000000000000",
  "type": "totp",
  "totp": {
    "qr_code": "<svg-or-data-url>",
    "secret": "<base32-secret>",
    "uri": "otpauth://totp/Hauth:user@example.com?secret=..."
  }
}
```

#### `POST /factors/{factor_id}/challenge`

Creates a TOTP challenge.

Response `200`:

```json
{
  "id": "00000000-0000-0000-0000-000000000000",
  "expires_at": 1780000000
}
```

#### `POST /factors/{factor_id}/verify`

Verifies a TOTP challenge.

Request:

```json
{
  "challenge_id": "00000000-0000-0000-0000-000000000000",
  "code": "123456"
}
```

Response `200` is a session response with elevated `aal` and `amr` claims.

#### `DELETE /factors/{factor_id}`

Served as a compatibility placeholder. TOTP factor unenrollment is not
implemented in v0.1.

Response `501`:

```json
{
  "code": "not_implemented",
  "msg": "Not implemented"
}
```

### Admin

Admin endpoints require service-role authentication.

#### `GET /admin/users?page=1&per_page=50`

Response `200`:

```json
{
  "aud": "authenticated",
  "users": []
}
```

#### `POST /admin/users`

Creates a user.

Request:

```json
{
  "email": "user@example.com",
  "password": "correct horse battery staple",
  "email_confirm": true,
  "user_metadata": {},
  "app_metadata": {}
}
```

Response `200` is a user object.

#### `GET /admin/users/{user_id}`

Response `200` is a user object.

#### `PUT /admin/users/{user_id}`

Updates admin-controlled user fields.

Request:

```json
{
  "email": "new@example.com",
  "password": "new password",
  "email_confirm": true,
  "user_metadata": {},
  "app_metadata": {},
  "ban_duration": "24h"
}
```

Response `200` is a user object.

#### `DELETE /admin/users/{user_id}`

Deletes a user.

Response `200` is the deleted user object.

#### `GET /admin/users/{user_id}/identities`

Lists linked identities for a user.

Response `200`:

```json
{
  "identities": []
}
```

#### `DELETE /admin/users/{user_id}/identities/{identity_id}`

Served as a compatibility placeholder. Identity unlinking is not implemented in
v0.1.

Response `501`:

```json
{
  "code": "not_implemented",
  "msg": "Not implemented"
}
```

#### `POST /admin/generate_link`

Served as a compatibility placeholder. Admin-generated action links are not
implemented in v0.1.

Request:

```json
{
  "type": "signup",
  "email": "user@example.com",
  "password": "optional-for-signup",
  "data": {},
  "redirect_to": "https://example.com/welcome"
}
```

Supported v0.1 `type` values:

- `signup`
- `recovery`
- `invite`
- `email_change_current`
- `email_change_new`

Response `501`:

```json
{
  "code": "not_implemented",
  "msg": "Not implemented"
}
```

#### `POST /admin/invite`

Invites a user by email.

Request:

```json
{
  "email": "user@example.com",
  "data": {}
}
```

Response `200` is a user object.

#### Legacy admin placeholders

The following Supabase-compatible legacy admin paths are served as
compatibility placeholders and return the documented `501` placeholder body:

- `GET /admin/providers`
- `PUT /admin/providers`
- `GET /admin/email_templates`
- `PUT /admin/email_templates`
- `GET /admin/webhook_deliveries`
- `GET /admin/webhook_deliveries/{delivery_id}`
- `POST /admin/webhook_deliveries/{delivery_id}/retry`

Use the implemented kebab-case email template CRUD routes
`/admin/email-templates...` for template administration. Use the implemented
webhook delivery routes `/admin/webhooks/{subscription_id}/deliveries`,
`/admin/deliveries/{delivery_id}`, and
`/admin/deliveries/{delivery_id}/retry` for delivery inspection and retry.

## JWT Contract

Access tokens are JWTs. ES256 is the default signing algorithm for new Hauth
deployments. HS256 must be supported for Supabase compatibility when an
operator configures a legacy shared JWT secret.

Required claims for user access tokens:

| Claim | Type | v0.1 value |
| --- | --- | --- |
| `iss` | string | Auth issuer URL |
| `aud` | string | `authenticated` |
| `exp` | number | Unix expiry timestamp |
| `iat` | number | Unix issued-at timestamp |
| `sub` | string | User UUID |
| `role` | string | `authenticated` |
| `session_id` | string | Session UUID |
| `email` | string | User email |
| `aal` | string | `aal1` or `aal2` |
| `amr` | array | Authentication methods used |
| `app_metadata` | object | Server-controlled metadata |
| `user_metadata` | object | User-controlled metadata |
| `is_anonymous` | boolean | Always `false` in v0.1 |

Optional claims:

| Claim | Type | Notes |
| --- | --- | --- |
| `jti` | string | Unique JWT ID, if configured |
| `nbf` | number | Not-before timestamp, if configured |
| `phone` | string | Not emitted in v0.1 except if future-compatible data exists |

`aal` values:

- `aal1`: password or OAuth session without verified MFA.
- `aal2`: session after successful TOTP verification.

`amr[].method` values emitted in v0.1:

- `password`
- `oauth`
- `token_refresh`
- `totp`
- `recovery`
- `invite`
- `email/signup`

Example password JWT payload:

```json
{
  "iss": "https://auth.example.com/auth/v1",
  "aud": "authenticated",
  "exp": 1780003600,
  "iat": 1780000000,
  "sub": "00000000-0000-0000-0000-000000000000",
  "role": "authenticated",
  "session_id": "00000000-0000-0000-0000-000000000001",
  "email": "user@example.com",
  "aal": "aal1",
  "amr": [
    {
      "method": "password",
      "timestamp": 1780000000
    }
  ],
  "app_metadata": {
    "provider": "email",
    "providers": ["email"]
  },
  "user_metadata": {},
  "is_anonymous": false
}
```

## Database Compatibility Commitments

Hauth v0.1 owns the `auth` schema in the operator's Postgres database.

The initial migration must create tables compatible enough for existing
Supabase-style RLS policies and direct reads:

- `auth.users`
- `auth.identities`
- `auth.sessions`
- `auth.refresh_tokens`
- `auth.mfa_factors`

Compatibility means preserving public table names, primary IDs, user foreign
keys, timestamp columns, metadata JSON fields, email identity fields, session
links, refresh-token links, and MFA factor status/type fields. Hauth does not
commit to preserving GoTrue internal helper function names, trigger names, or
private implementation tables.

## Error Contract

Errors are JSON unless an OAuth or verification browser flow redirects.

Preferred shape:

```json
{
  "error": "invalid_request",
  "error_description": "Human-readable explanation"
}
```

Compatibility shape also accepted where Supabase clients expect it:

```json
{
  "code": 400,
  "msg": "Human-readable explanation"
}
```

Stable v0.1 status code commitments:

- `400`: malformed request or unsupported parameter.
- `401`: missing or invalid bearer token.
- `403`: authenticated but not allowed, including non-service-role admin access.
- `404`: requested user, factor, or identity does not exist.
- `422`: syntactically valid request that violates validation or state rules.
- `429`: rate limited.

Exact error messages are not part of the compatibility contract.

## v0.1 Non-Goals

The following are explicitly out of scope for v0.1:

- Phone/SMS auth and WhatsApp auth.
- Magic link and OTP sign-in as first-class login methods.
- Anonymous users.
- WebAuthn/passkeys.
- SAML/SSO.
- Additional OAuth providers beyond Google and GitHub.
- Captcha enforcement.
- `/reauthenticate`.
- Admin audit log endpoints.
- Admin UI.
- Legacy snake-case webhook delivery log and retry endpoints under
  `/admin/webhook_deliveries`.
- Hot-reloaded provider administration.
- Supabase proprietary hosted-platform integrations.
- Bug-for-bug compatibility with known GoTrue bugs.
